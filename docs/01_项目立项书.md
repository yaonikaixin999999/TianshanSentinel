# 项目立项书

## 一、项目概况

项目名称：天山哨兵

项目周期：20 天，建议 4 人小组

项目类型：软件工程 + 人工智能综合实训

核心成果：训练代码、推理模型、Web 系统、数据库、测试报告、课程论文与答辩材料。

## 二、问题陈述

多时相遥感影像数量快速增长，但人工逐幅对比成本高、结论主观且难以留痕。传统像素差分容易把光照、色彩和配准误差当作真实变化。项目拟构建一套可复现实验和可审计应用，把深度变化检测模型转化为可操作的软件系统。

## 三、总体目标

1. 完成双时相图像上传、配准、变化检测、后处理与可视化闭环。
2. 在 LEVIR-CD 测试集上以 IoU、F1、Precision、Recall 衡量模型，所有数值从脚本产生。
3. 将模型导出为 ONNX，使普通 CPU 能完成单组 256 x 256 影像推理。
4. 保存分析历史和变化斑块，保证结果可追溯。
5. 形成论文、需求、设计、测试与部署文档。

## 四、范围

### 范围内

- RGB 双时相图像。
- 二分类像素级变化检测。
- 自动配准、置信度、不确定性、面积统计和风险分级。
- 单机、Docker 和云 GPU 训练流程。

### 范围外

- 未经标注的变化类别识别，如区分建筑、水体和植被。
- GIS 坐标投影和真实面积换算；若缺少 GSD，仅报告像素占比。
- 面向生产执法的高可用集群和用户权限体系。

## 五、角色分工

| 角色 | 主要任务 | 核心产物 |
|---|---|---|
| 组长/架构 | 需求、任务拆分、代码合并、答辩 | 计划、架构、集成版本 |
| 算法工程 | 数据、模型、损失、训练、评估 | 权重、指标、可视化样例 |
| 后端工程 | API、推理封装、SQLite、部署 | 接口、数据库、容器 |
| 前端与测试 | 看板、图像对比、测试、文档 | Web 页面、测试报告、演示 |

三人组可合并“后端”和“前端与测试”；五人组可增加数据与论文负责人。

## 六、20 天里程碑

| 阶段 | 天数 | 验收点 |
|---|---:|---|
| 立项与数据 | 1-3 | 需求冻结，数据目录通过校验 |
| 算法基线 | 4-7 | 小样本过拟合成功，训练日志可复现 |
| 模型优化 | 8-11 | 完整训练、评估和误差分析 |
| 系统开发 | 12-15 | API、前端、数据库联调完成 |
| 部署测试 | 16-18 | ONNX、CPU 推理、测试报告完成 |
| 论文答辩 | 19-20 | 论文回填真实数据，演示脚本演练 |

## 七、验收指标

- 软件：PNG/JPEG/TIFF 上传成功率 100%，历史记录可查询，非法文件返回明确错误。
- 算法：报告 IoU、F1、Precision、Recall；不预设虚假达标值，以公开基线和误差分析为依据。
- 性能：记录 GPU 训练耗时、ONNX CPU 平均延迟和模型文件大小。
- 质量：自动测试全部通过，前端可构建，论文中的指标能追溯到 `metrics.json`。

## 八、主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据下载慢 | 延误训练 | 提前上传云盘；先用 20 对样本验证链路 |
| 训练显存不足 | 批量过小或 OOM | 降低 batch size，开启 AMP，使用 256 切片 |
| 影像未配准 | 伪变化增多 | 自动配准并显示是否成功；失败时人工预处理 |
| 指标与论文不一致 | 学术风险 | 只从评估脚本导出，保留配置和日志 |
| 本地推理慢 | 演示卡顿 | ONNX、ResNet18、固定尺寸和预热 |
